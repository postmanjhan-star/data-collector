# MQTT shadow transport
Existing SyncAgent, ScanStore, GUI and installer are reused. Set Server URL to mqtts://BROKER:8883 and Collector ID to a unique ASCII identifier. The existing DPAPI secret is used as MQTT password; username equals Collector ID. Plain mqtt:// is loopback-only. Use a new isolated SQLite database per pilot. Do not point production clients at the test system. Topic smt/test/v1/collectors/<id>/scans accepts the existing HF811 batch envelope. ACK on /ack includes collector_id, payload_sha256 and receipt. No retained messages. A valid ACK is required before changing SQLite state. HTTP remains the default and unchanged. This phase collects raw scans only, including duplicate and NOREAD flags; it does NOT infer board completion, pair scanners, calculate pass_qty or deduct reels. Broker ACL must prohibit collector publish to ACK/other topics and restrict Soda subscription/publication. Use separate test credentials; never share rack credentials. Test connection checks broker connection/subscribe only. Use Soda private integration workflow for the gated installer.
